# UI Implementation Plan

## Overview

Vue 3 + Vite 8 + TypeScript 6 + Pinia + Tailwind CSS v4 + shadcn-vue (new-york, neutral). Two roles: **owner** (one hardcoded profile, no auth) and **guest** (no account). API base URL: `http://localhost:4010` (Prism mock).

## 2. Routes

| Path | View | Description |
|------|------|-------------|
| `/` | PublicEventTypesView | Guest: browse event types |
| `/book/:eventTypeId` | PublicBookingView | Guest: pick slot + book |
| `/admin` | AdminDashboardView | Owner: dashboard |
| `/admin/event-types` | AdminEventTypesView | Owner: CRUD event types |
| `/admin/bookings` | AdminBookingsView | Owner: upcoming bookings |
| `/admin/settings` | AdminSettingsView | Owner: working hours + timezone |

## 3. API layer (maps directly to TypeSpec)

**`api/types.ts`** — all TS interfaces from TypeSpec:
```ts
EventType, EventTypeCreate, EventTypeUpdate, Slot, GuestInfo, Booking,
BookingCreate, ApiError, TimeOfDay, DaySchedule, OwnerSettings
```

**`api/client.ts`** — `get<T>`, `post<T>`, `patch<T>`, `put<T>`, `del<T>`. Base URL from env `VITE_API_BASE_URL`, fallback `http://localhost:4010`. Throws `ApiError` on non-2xx.

**Module files:**
- `event-types.ts` — 6 functions (admin list/create/get/patch/delete + public list/get)
- `bookings.ts` — 2 functions (admin list + public create)
- `slots.ts` — 1 function (list by eventTypeId)
- `settings.ts` — 2 functions (get + update)

## 4. Pinia stores

## 5. Components breakdown

### Layout
**AppHeader.vue** — Logo left ("CalComClone"), nav links to `/` and `/admin` on the right.

### Event Types
**EventTypeCard.vue** — Props: `eventType`, `mode: 'guest' \| 'admin'`. Guest has "Book" button. Admin has "Edit"/"Delete". Shows name, description, duration badge.

**EventTypeForm.vue** — Dialog. Fields: name (Input), description (Textarea), durationMinutes (Input number). Validates required + > 0. Props: `eventType?` (for edit), `open`. Emits: `close`, `saved`.

### Bookings
**BookingList.vue** — Table with columns: Guest Name, Event Type, Date/Time, Created At. Props: `bookings`, `loading`. Skeleton loading rows. "No bookings" empty state.

### Slots
**SlotCalendar.vue** — 14-day date picker using a row of date tabs/buttons. Selected date shows available time slots as a grid of clickable buttons. v-model emits `selectedSlot`. Days without slots are greyed out. Dates computed locally from `Date.now()` + 14 days.

**GuestBookingForm.vue** — Shows selected date/time summary. Name Input with label. "Confirm Booking" Button (disabled until name is non-empty and slot selected). Props: `slot`, `loading`. Emits: `book`.

### Settings
**WorkingHoursForm.vue** — Timezone Input/Select. For each day (Mon–Sun): `isWorking` Checkbox toggle, start time Select/Input (hour:minute), end time Select/Input. "Save" Button. Loads current settings on mount via store.

## 6. Views

**PublicEventTypesView.vue** — Grid of EventTypeCard (guest mode). Skeleton loading. Empty state: "No event types available yet."

**PublicBookingView.vue** — Route param `eventTypeId`. Shows event type name + description header. SlotCalendar → GuestBookingForm flow. Success state: green confirmation with booked time. Error state: red alert.

**AdminDashboardView.vue** — 3 stat cards: "Event Types" (count), "Upcoming Bookings" (count), "Settings" (configured/not). Links to each section.

**AdminEventTypesView.vue** — "Create Event Type" button opens EventTypeForm. Table of existing types with Edit (opens form pre-filled) and Delete (confirm dialog) actions.

**AdminBookingsView.vue** — BookingList component. Fetches on mount.

**AdminSettingsView.vue** — WorkingHoursForm. Fetches on mount, shows form, save button updates.
